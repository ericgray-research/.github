# Contributing

These repositories are **open to critique, not to contribution.**

## What is welcome

**Issues that point out a flaw.** For example: a prediction that was registered badly, a method that
cannot measure what it claims, a source misread, a missing control, a bug in code. Please cite the
file and the commit (or line) you are pointing at, so the critique can be checked against the exact
record it concerns.

A critique that holds is answered in the record: a new commit that names the flaw and what it
changes. Tell me in the issue if you want to be credited by name.

## What is not accepted

**Pull requests.** These are authored research records, and their provenance depends on every change
being made and accounted for by their author. Pull requests are switched off where the platform
allows it.

**Feature requests** for tools here are read, but tools grow from the research that needs them, not
from requests.

## Security issues

Do not open a public issue for a security vulnerability. See [SECURITY.md](SECURITY.md).

## Pace

This is one person's work. Issues are read; replies come when they come.
